# 多肽公司与合作调研

回答：谁在多肽上押注什么，交易发生在什么阶段、为何合作、谁负责什么，权利和资金如何变化？可从公司、交易对手、资产或一项合作开始，不要求先建靶点专题。

先读 [共享研究与数据协议](../../references/research-contract.md)，再读 state 和 `python3 atlas.py plan --company Hansoh --alias 翰森 --alias 豪森`。本 skill 以公开多肽业务为界；同公司其他模态只有解释战略或排除误分类时使用。

## 收录范围

同时追踪“具体多肽资产的交易”和“多肽公司的能力合作”。后者包括发现/筛选/AI设计平台、共同研发、递送/制剂、合成/CMC/制造服务、平台许可、战略投资及合资；无需已有靶点、分子或临床项目。单纯会议出席、园区入驻或泛泛合作意向不当成已签项目，须说明协议是否约束性、合作内容及多肽关联。

平台合作单独用 deals.eventKind=platform，未披露关联留空；不捏造分子/靶点，不为关系图建虚构资产。平台访问权、具体资产权利及股权投资分别描述；同一公告包含多个组成可在同事件说明，不因重复报道新增交易。明确后续融资/合同修订才按新事件另记。

## 独立公司调研

1. 先列法律主体、中英文品牌、旧名、子公司、专利申请人名称及证券代码；集团、研发子公司、合同签约方和投资者不能混成一个角色。明确公司专题是全多肽布局，还是仅某靶点/交易的补查。
2. 从官网管线/平台和最新年报/中报、交易所/SEC 披露，发现公开多肽资产与合作，不依赖网站已有分子。沿中英文名称、临床代号/新受让方代号、申请人及交易对手检索；含无明确靶点的平台、临床前项目、已终止/归还权利的交易。论文不是公司合作的必备前提。
3. 额外执行公司名/旧名 × 合作/战略合作/平台/共同研发/技术许可/递送/制造/投资（及英文）的检索，不强制每条查询出现 peptide，防止原稿仅写 Synova 等品牌名而漏检；由原文确认多肽相关性。对手方尤其 MNC 的年报、partnering 新闻、投资组合反查同一合作。核对早期公司旧名与中文名，例如元思生肽/Syneron Bio/呈元科技，不自动合并不同法律主体。
4. 每个线索反查双方公告和后续证券文件/合同附件。区分披露日、生效/签约日、交割、付款、技术转移、开始试验和终止；月份未知具体日时 date=null,signedPeriod=YYYY-MM，不把新闻日期替代签约日期。新代号有原文明示才合并。
5. 平台合作提取：合作技术/平台品牌、疾病领域、项目数（未披露即留空）、双方角色、平台访问/排他性/地域、合作时发现或研发阶段与后续变化。平台合作不套用不存在的临床分期。提取项目范围、地域（含香港/澳门/台湾的独立处理）、适应证、排他性、再许可、开发/制造/商业化责任；平台合同不补猜靶点。动机分官方、分析、未披露。按签约时的已证实阶段解释交易，而不是用今天阶段回填。
6. 合计口径不可拆猜：例如元思生肽–阿斯利康2025公告的7500万美元为首付+潜在近期里程碑合计，不能填为纯首付或已付；最高34亿美元是额外潜在里程碑，股权投资独立且未披露金额。使用 financialSummary/financialNotes 明示组合，无法单列的 upfront/paid=null。MNC在华总投资或整轮融资总额不能归给一家公司或一个投资人。金额分约定首付款、已付首付款、逐项实际里程碑、未触发里程碑、版税、股权融资；保留币种、条件和截至时点。按每产品与全合同上限分开；潜在总额不等于到账，融资承诺不等于新现金到账，投资额不算许可首付款。签约、增资/反向合并、合同修订是同一商业链的不同事件，不重复累加旧条款。
7. 按申请人/受让人独立搜专利家族、优先权与公开日、结构/SAR/动物/配方内容。专利公开、临床代码和许可资产的对应关系单独核验；共享公司/靶点不证明同分子，待审申请不等于授权或法律有效性。技术明细由靶点 skill 补查。
8. 对重要交易查到本次截至日的履行、修订、终止、权利归还和新开发主体；同时核对不利数据、暂停和冲突。不能从正面新闻推导全面安全性或确定成功。除用户限定单笔交易外，至少检索该公司其他多肽方向以防把一个靶点当成全部布局；未完成则明列范围。

## 单用与联用

- 单用：公司/交易专题可只提交 companies、sources、deals、receipts 和 gaps。未披露靶点保留空 targetIds；不为满足页面而造分子。发现的明确资产可提交最小身份和确证的阶段；不强制开展全部 SAR 调研。
- 公司资产组合按[入库前分类核对](../../references/research-contract.md#入库前分类核对)确认具名项目身份。论文署名、专利申请人或平台合作参与方不使其全部实验编号成为公司资产；交易涉及平台或未具名项目时保留原始范围，不把同靶点SAR编号逐个挂到交易。
- 联用：读取 [peptide-target-research](../peptide-target-research/SKILL.md)，交接已确认公司/分子 ID、别名、原始链接、专利家族及未确认映射，仅核对指定资产的机制、结构/谱系与阶段；不重复抓取双方已核查资料。靶点 skill 发现交易后返回此处，补完权利、支付、制造责任及后续变化。
- 两者相交（例如 PepStar–HCXT-2001 或 Hansoh–HS-20118/AVR-001）仍只有一个分子身份和每事件一个交易 ID；一篇披露可同时作为技术与商业证据。复用 receipts/gaps 作交接，不建立第二份知识库。

## 交付与停止条件

通过 CLI commit 更新公司、交易、证据与缺口；给出公开多肽布局、关键事件及截至时点，不以公司全部新闻堆砌报告。保存实际执行的中英文检索、来源类别、交易对手反查和后续核查回执。明确哪些项目/财务条款、专利映射与履行仍未知。趋势判断标为分析，引用事实并保留反证；有限补查不宣称完成全公司尽调。

补材料与复查前按共享协议检查已解决/无法获取的问题；复用旧 gap 并保留归档原因，避免公司公告反查将同一获取失败问题重新弹出。收到用户补充后同步提交事实和原问题的结论状态。


## 另外两个入口

用户补交材料、纠错或关闭问题时，使用[补充材料核验与更新](../peptide-evidence-update/SKILL.md)的闭环，不另建审阅流程。需要跨资料的方向判断、对比历史或机会假设时，交给[情报综合与观察](../peptide-intelligence-synthesis/SKILL.md)；本skill负责支持判断的事实，不把未核实推断写成科学/商业事实。按需交接已有ID和范围即可，不强制每次都调用四项。

## 展示文字

遵循[共享协议的展示文案规则](../../references/research-contract.md#展示文案)：直接写事实与具体未知，检索过程保存在回执和历史。提交前检查标题、摘要、条款和观察，修正套话后再写入数据库。
