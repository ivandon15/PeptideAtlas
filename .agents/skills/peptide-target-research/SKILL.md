# 多肽靶点调研

回答：这个靶点有哪些公开分子、如何被发现和优化、相互如何关联、每个分子实际走到了哪里？范围包括肽偶联物与肽蛋白融合物；保留真实模态，不能把同靶点抗体/小分子算作多肽。

先读 [共享研究与数据协议](../../references/research-contract.md)，再运行 `python3 atlas.py state` 和 `python3 atlas.py plan --target IL23R --alias IL-23R --alias 白细胞介素23受体`。工具只生成计划；检索和科学核实由当前 Codex 实际执行。

## 发现与逐项核实

1. 定义物种、变体、结构域、受体/配体及作用机制；列中英文拼写、旧名与临床代号。IL23R 结合肽与 IL-23p19 结合肽不是同一靶点；pan-RAS 与 KRAS G12D 不互换。
2. 沿三种入口建立候选清单：论文/会议/SI 及参考文献与后续引用；靶点/机制检索的专利家族与实施例；临床登记/监管/公司管线。检索含 peptide、cyclic/macrocyclic、miniprotein/minibinder 等实际相关模态，不仅查论文标题或最近一年。
3. 独立做产业反查：中英文靶点 × 口服肽/许可/授权/收购/合作（及英文对应词），公司管线、交易所/证券披露；对新发现的申请人、开发方、受让方用中英文法律名和全部代号反查。检查尚无论文的中国及其他地区临床资产。不能只从已知分子名单开始，也不能以 Europe PMC + ClinicalTrials.gov 代替此步骤。
4. 对每个已公开可识别编号建立带命名空间的身份；论文召回阶段先完整登记论文×靶点关联，不强制把同篇全部序列变成分子记录。展开序列调查时登记本轮范围内全部候选而非只取 lead；表页/实施例未完成则保留具体范围。不能从总体命中率生成虚构分子。序列未核实填 null，临床资产仍保留身份。
5. 按分子核实发现方法、SAR/成药性、专利与临床前、CMC/制剂、临床/监管；公司/交易是交叉检查入口，深入合同由公司 skill 负责。计算起源与实验验证分开；Kd/Ki/IC50、物种、构建体和实验条件分开。计划实验/预计入组不是已实施。精确结构保留 D/L、非天然残基、端基、桥连和盐型。
6. 谱系边只用原文支持：直接衍生、同系列、资源转向分别编码。阶段与活动状态分别证实；PCC 不由临床开始日推算。CMC 复用 evidence（line=method,topic=cmc），区分砌块/片段/API/制剂及路线版本，不新增同一药物或提升临床阶段。

## 计算设计的双向召回

不要只由已知分子找论文。同步走两条线：
- 靶点 → 中英文/基因/受体亚基/物种/变体/PPI伙伴别名 × peptide/minibinder/macrocycle、de novo/redesign/motif grafting/interface mimicry/hallucination/sequence optimization。标题无靶点的模型论文仍需查正文、图注、SI、作者代码和数据表。
- 方法 → 论文/预印本/会议/作者GitHub → 逐一列出实际涉及的靶点，区分计算评估集合、真正合成测试、未检出结合、细胞功能和动物验证。模型的训练数据或引用旧binder不当作该模型新设计的阳性结果。

已知方法词表是可扩展起点：AfCycDesign/ColabDesign、RFpeptides、BindCraft短肽评估、PepMimic、Mirror-Peptidizer、HFGuidedDesign/HighFold、AnewOmni、Latent-X2、ProteinMPNN/GRU-VAE及结构指导理性改造。实验de novo筛选不自动归计算de novo；同源/模板改造、界面模拟和纯结构预测须按真实工作类型标识。

用户旧表如有提供，仅作召回基准，不是事实来源：逐个读取靶点页、量化主表、实测未定量与待核实清单，按“靶点×DOI/arXiv×版本”归并。为每条线索记录已召回/原文确认/关联待核/排除及理由、实际访问范围和原文定位；未补齐的不能用一句“覆盖23靶点”掩盖。仓库自带回归基准见 `data/computational-recall-2026-10-27.json`（相对仓库根目录），不依赖使用者持有旧工作簿；检查基准论文和靶点映射，再继续向外检索，23不是固定范围上限。

网页按论文归档时可只提交sources+publication系列+series关联evidence，无需先枚举全部分子。每靶点一条研究关联可包含计算流程/设计类别/验证级别（validationLevel）和限制；同篇多靶点全局只算1篇。实验未定量、弱结合、阴性及未核实序列保留各自状态，不都换算成命中binder。论文版本/预印本/镜像按documentGroup归一，检查勘误；最新核查日期不覆盖首发日期。不得用旧表中的化学序列、Kd、PDB或本地路径直接生成已核实分子事实。

## 与公司 skill 衔接

可独立完成靶点调研：仍需产业反查以发现分子，但不因此扩展调查每家公司全部管线。发现具体多肽交易、权利变化或战略投资，读取 [peptide-company-research](../peptide-company-research/SKILL.md)，仅核实该靶点关联交易及明确关系。若用户要求综合调研，再扩至相关公司多肽布局。

反向接收公司 skill 的线索时，复用已有 molecule/company/source IDs 和别名；核验受体、模态、专利实施例映射与阶段，不把商务稿里的“IL-23”自动解释成 IL23R。未能确认的关联进入同一个 gap，不能强连谱系。

## 交付与停止条件

通过 CLI commit 写入分子、系列、证据、谱系和缺口。按六条范围保存真实回执；交代已枚举/未枚举的来源，当前证实阶段与计划阶段，以及申请人/公司反查是否做过。一次有限调研可以结束为“部分覆盖”，不能称为靶点全量。网页刷新核查身份、引用、时间轴，复用已有记录给摘要；后续发现属于同一演变历史。

网页归类按共享协议的“页面分类与问题归档”：区分模型验证论文与持续研发系列，记录 researchFocus 的原文依据；每个分子/系列补查后续研究与独立专利家族。问题解决或人工确认无法获取后更新原 gap，不能只修改前台显示。


## 另外两个入口

用户补交材料、纠错或关闭问题时，使用[补充材料核验与更新](../peptide-evidence-update/SKILL.md)的闭环，不另建审阅流程。需要跨资料的方向判断、对比历史或机会假设时，交给[情报综合与观察](../peptide-intelligence-synthesis/SKILL.md)；本skill负责支持判断的事实，不把未核实推断写成科学/商业事实。按需交接已有ID和范围即可，不强制每次都调用四项。
